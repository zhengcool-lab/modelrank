# ModelRank 模型榜 · UI/UX 设计评审（首页 + 模型详情页）

- **评审日期**：2026-10-28（周三）
- **评审页面**：
  - 首页/榜单：https://modelrank-1br.pages.dev/
  - 模型详情页：https://modelrank-1br.pages.dev/detail/gpt-5
- **评审视口**：桌面 1440×900、移动 375×812（device_scale 2x）
- **评审方式**：无头浏览器真实渲染截图 + 抓取 HTML / CSS（`_next/static/css/*.css`）+ 对比度逐色核算
- **问题总数**：20 个（P0×1，P1×11，P2×8）

> 说明：以下对比度为在对应背景色上用 WCAG 相对亮度公式实测值；4.5:1 为正文 AA 门槛，3:1 为大字/图形 AA 门槛。

---

## 【首页 / 榜单】

### 1. [P1] 同一批 Top 模型在首页重复出现两遍
- **位置**：页面中段 —— 先有一张完整排行榜表格（排名 1–25，含推理/代码/中文/多模态小分），表格底部出现「共 128 个模型 · 查看完整榜单」按钮；紧接着下方又是一整套大卡片榜单（同样从排名 1 GPT-5 开始到 25），末尾再来一个「查看完整榜单 →」。
- **现象**：同一批 25 个模型、同样的排名/分数/价格在首屏被展示两次，用户无法判断哪份才是"当前榜单"，且两个"查看完整榜单"入口并存，信息架构冗余、浪费首屏。
- **建议**：二选一。要么只保留表格（卡片作为 Top3 编辑精选），要么只保留卡片；两个"查看完整榜单"入口合并为一个，并明确第二块的定位（如"上升最快"而非重复 Top25）。

### 2. [P1] 辅助灰文字对比度仅 3.24:1，不达标
- **位置**：表格内厂商上下文（"OpenAI · 128K 上下文"）、置信区间（"±2.1 (CI)"）、首页副标题、页脚链接。
- **现象**：这些文字使用 `--mr-text-3:#86909c`，在白色卡片底上实测 **3.24:1**，低于 WCAG AA 正文 4.5:1；在 `#f2f2f7` 页面底色上更只有 **2.90:1**。小字号（10–12px）下尤其吃力。
- **建议**：将 `--mr-text-3` 加深到 `#5b6470` 左右（实测 ≥4.6:1），`--mr-text-4:#a9aeb8`（实测 2.23:1）仅可用于占位符，不得用于真实数据。

### 3. [P1] 涨/跌箭头颜色对比度不足
- **位置**：评分列右侧的趋势标记，如"96.3 ↑2.1""94.1 ↓1.3"。
- **现象**：上涨绿 `--mr-up:#2e9e5b` 在白底实测 **3.41:1**，下跌红 `--mr-down:#d4481a` 实测 **4.43:1**（差一点点），均未过 AA 4.5:1；红绿色同时承担涨跌语义，对红绿色盲用户不友好（还靠箭头形状，但颜色本身偏弱）。
- **建议**：绿色加深到 `#1f7a44`、红色加深到 `#c0392b`；并在箭头外辅以"↑/↓"符号（已有），不要只靠颜色区分涨跌。

### 4. [P1] 全站基础字号偏小，维度小分仅 10px
- **位置**：表格"能力"四宫格小分（推理 94 / 代码 90 / 中文 88 / 多模态 96）。
- **现象**：CSS 统计显示 `font-size:10px` 出现 101 处、`12px` 出现 403 处、基础 `body` 字号仅 13px。10px 的维度小分在桌面端需要凑近辨认，移动端更是糊成一团。
- **建议**：维度小分提升到 12px，正文最小 13→14px；榜单数据类界面建议正文 14px、辅助 12px 起步。

### 5. [P1] 全站没有悬停反馈、没有键盘焦点框
- **位置**：表格行、模型名链接、榜单卡片、按钮、顶部导航。
- **现象**：应用 CSS 中 `:hover` 规则数为 **0**、`transition` 次数为 **0**、`:focus`/`:focus-visible` 为 **0**。鼠标划过表格行/卡片无任何底色变化，模型名看不出可点；键盘 Tab 时没有可见焦点框，可访问性差。
- **建议**：表格行 hover 加 `#f7f8fa` 背景过渡；模型名 hover 显示下划线或整行可点；全局补 `:focus-visible{outline:2px solid var(--mr-primary);offset:2px}`；所有可点元素加 150ms 过渡。

### 6. [P1] 移动端标签随模型名长度错位
- **位置**：移动端榜单卡片头部（375px 下）。
- **现象**：第 1 名 GPT-5 的"闭源"+"S"档标签排在名字右侧同一行；第 2 名 Claude Opus 4.5 名字更长，"闭源"被挤到右上角、"A"档标签掉到第二行，导致不同卡片的标签位置左右不一、上下不一，视觉节奏断裂。
- **建议**：标签固定排在模型名**下方**一行（或名字右侧固定区域），不随名字长度浮动；档位徽标与"开源/闭源"标签统一对齐基线。

### 7. [P1] "性价比"列用语与颜色语义模糊
- **位置**：表格"性价比"列，以及筛选器"性价比档 S/A/B/C"。
- **现象**：表格里用"高 / 中 / 低"文字 + 浅底色表达，但截图中"低"档是浅绿底、"中"是灰底，颜色与文字的好坏语义对不上（用户会以为"低"=不好）；而筛选器用的是 S/A/B/C 字母档，两套体系并存，卡片列表里这一列又直接消失。
- **建议**：统一为 S/A/B/C 档位色块（与筛选器一致），删除"高/中/低"模糊表述；卡片中也应显示档位徽标。

### 8. [P2] 数字列未右对齐、未使用等宽数字
- **位置**：表格"评分"列（96.3 / 94.1 / 93.8…）、"价格（输入/输出）"列。
- **现象**：所有数字左对齐，纵向扫读小数点不对齐（96.3 与 94.1 的小数点参差）；字体为系统比例数字，位数变化时位置跳动。
- **建议**：数字列 `text-align:right`，并加 `font-variant-numeric: tabular-nums`，让小数点纵向成列。

### 9. [P2] 圆角三种规格并存
- **位置**：卡片 `border-radius:8px`，按钮/输入框/标签 `4px`，顶部"模型榜"角标 `2px`。
- **现象**：同一页面出现 8px / 4px / 2px 三种圆角，缺乏统一规范，控件显得"硬"、卡片显得"圆"。
- **建议**：统一为一套令牌，如卡片 12px、控件 8px；至少把按钮从 4px 提到 8px 与卡片协调。

### 10. [P2] 图标风格混用（emoji / Unicode / SVG / 位图）
- **位置**：顶部导航右侧——"🔍 搜索"用 emoji、"🌙/◐ 深色"用 emoji 或字符、"📈 订阅变动提醒"用 emoji、汉堡菜单用 SVG 线条、厂商 logo 用彩色位图。
- **现象**：四种图标风格混在同一行导航里，emoji 在 Windows/Android 下渲染颜色和尺寸都不一致。
- **建议**：搜索、主题、菜单统一为同一套线性 SVG 图标（与汉堡菜单一致），去掉 emoji 字符。

### 11. [P2] Hero 主标题层级偏弱
- **位置**：页面顶部"大模型能力排行榜"。
- **现象**：桌面端主标题仅 24px / 600，与 13px 正文差距不大，榜单首页缺乏视觉重心；副标题又是 13px 灰字，主次拉不开。
- **建议**：桌面主标题提升到 32–36px / 700，副标题保持 14px，形成清晰三级层级。

### 12. [P2] 日期/时间格式不统一
- **位置**：首页副标题"数据更新于 10-16 08:00"（月-日，缺年份）、详情页"价格更新于 2026-10-12"（ISO）、新闻区"2 小时前 / 昨天"。
- **现象**：三处时间格式三种写法，"10-16"不写年份在跨年时会歧义。
- **建议**：统一为相对时间（"2 小时前"）+ hover/tooltip 显示完整 ISO 日期；数据表头注明"更新于 2026-10-16"。

## 【模型详情页（GPT-5）】

### 13. [P0] 厂商 logo 裂图（404）
- **位置**：右侧栏"厂商背景"卡片。
- **现象**：`<img src="/vendor-logos/openai.png">`（40×40）实际返回 404，页面渲染为"裂图图标 + alt 文字 OpenAI"，且 alt 文字"Open/"折行到图标下方，非常刺眼；移动端同样裂图。其他厂商（deepseek/doubao/kimi 等）同路径亦有 404。
- **建议**：补全厂商 logo 静态资源；加 `onerror` 兜底——加载失败时显示首字彩色圆形头像（与列表中已有字母头像风格一致）。

### 14. [P1] 桌面端雷达图轴标签被裁切
- **位置**：中部"评分趋势（近 12 周）· 能力雷达"卡片（桌面 2fr+1fr 两栏布局）。
- **现象**：折线图与雷达图挤在同一行，雷达图右侧"多模态"轴标签被卡片右缘切掉（截图中只能看到半个字符），桌面端实际只露出"推理 / 数学 / 中文"3 个标签；移动端堆叠后 5 个轴（推理/代码/多模态/中文/数学）才完整。
- **建议**：该卡片在桌面也改为折线图在上、雷达图在下堆叠，或给雷达图预留足够宽度并允许标签溢出可见；不要让标签被卡片 overflow 裁切。

### 15. [P1] 评分维度口径与首页表格不一致
- **位置**：详情页雷达图 vs 首页排行榜"能力"列。
- **现象**：首页表格展示 4 个维度（推理 / 代码 / 中文 / 多模态），详情雷达图却是 5 个维度（推理 / 代码 / 数学 / 中文 / 多模态）——雷达多了"数学"，用户在首页看不到数学分，到详情页却出现，数据口径对不上。
- **建议**：统一维度定义。要么首页表格也展示 5 维，要么详情雷达收敛为 4 维并与榜单严格同名同义。

### 16. [P1] 详情页强插"企业咨询留资"表单
- **位置**：右侧栏（桌面）/ 页面最底部（移动 375 下被推到所有内容之后）。
- **现象**：用户在浏览一个模型的评分/价格/规格，右栏却直接放置姓名/工作邮箱/公司/需求描述 + "提交咨询"整块表单，属于强打断式商业转化；移动端看完所有模型信息后才看到它，转化路径突兀。
- **建议**：收进"联系商务"折叠面板或点击弹出的 modal，不要常驻占位；至少不要放在模型技术信息之前/之中。

### 17. [P1] "综合排名 #1 / 128"金色对比度仅 1.92:1
- **位置**：评分卡片右上"#1 / 128"。
- **现象**：使用 `--mr-gold:#e8b339`，在白底实测 **1.92:1**（银牌 `#c0c0c8` 更只有 1.81:1），大字号下也仅勉强接近 3:1 图形门槛，实际观感发飘、发淡。
- **建议**：金色加深到 `#b8860b` 或改为深色文字 `#1d1d1f` + 小奖牌图标；金/银/铜仅作点缀色，不作为主要文字色。

### 18. [P2] 价格卡三组数字基线与格式不统一
- **位置**："价格（API 按量）"卡片。
- **现象**："输入 ¥12 /M tok""输出 ¥60 /M tok"是大数字+小单位，而"同类中位数 ¥9 / ¥27"用斜杠把两个数挤在一起、字号更小，三种排版基线不一致；"¥12"与"/M tok"高低错落。
- **建议**：三组统一为"标签在上、大数字居中、单位小字对齐基线"；同类中位数也拆成"输入 ¥9 / 输出 ¥27"两行，与前两列同构。

### 19. [P2] "相关新闻"空状态过于简陋
- **位置**：价格卡下方"相关新闻"。
- **现象**：无数据时仅一行灰字"暂无相关新闻"，无图标、无插画、无引导动作。
- **建议**：加一个空状态插画/图标 + "订阅该模型更新"次要按钮，把空状态变成转化点。

### 20. [P2] 地区可用性用 emoji 对勾 + 详情头副标题被硬断词
- **位置**：右栏"地区可用性"（"✅ 中国大陆需合规代理接入 · ✅ 美国/欧洲直连"）；详情头部副标题（移动端断成"…更 / 新于 10-12"，"更新于"被从中间切开）。
- **现象**：绿色 emoji ✅ 在不同系统渲染不一、风格与全站线性图标不符；副标题在移动端允许在词中间断行，破坏中文阅读。
- **建议**：emoji 对勾换成统一 SVG check；副标题加 `word-break:keep-all` / `white-space` 处理，避免在"更新于"这类词中间断行。
