## 一、全局组件

### 【顶部导航栏 NavHeader】

1. **[P1] 激活导航链接未设置 `aria-current`，屏幕阅读器无法识别当前页**
   - 位置：桌面端导航项（榜单 / 模型库 / 对比器 / 成本计算器 / 方法论 / 新闻）
   - 现象：激活态仅通过 `fontWeight 600`、文字变 `--mr-primary`、底部 2px 下划线三个视觉手段表达，`<Link>` 上没有任何 `aria-current="page"` 属性。视障用户用读屏软件浏览导航时，只能听到一串相同的链接列表，无法知道自己在哪一页。
   - 建议：在 `isActive(item.href)` 为真的 `<Link>` 上补充 `aria-current={href === "/" ? "page" : "page"}`（或子路径用 `"location"`），与视觉激活态保持双通道一致。

2. **[P1] 汉堡菜单 aria-label 写死"打开菜单"，且面板缺少完整的可访问性与关闭行为**
   - 位置：移动端（<768px）右侧汉堡按钮及其下拉面板
   - 现象：按钮 `aria-label="打开菜单"` 在菜单展开后仍为"打开菜单"，与 `aria-expanded={true}` 的实际状态矛盾；面板没有 `aria-controls` 指向、没有 `aria-hidden`；菜单展开后按 Esc 无法关闭、点击面板外区域无法关闭、背景页面滚动未锁定。
   - 建议：aria-label 随 `menuOpen` 切换为"打开菜单 / 关闭菜单"，按钮加 `aria-controls="mobile-menu"`，面板加 `id="mobile-menu" role="navigation"`；监听 Esc 键与路由变化自动收起，并在展开时锁定 body 滚动。

3. **[P2] Sticky 导航滚动后无阴影/毛玻璃，与内容层缺乏 elevation 区分**
   - 位置：全局顶部导航栏（sticky, top:0, zIndex:40）
   - 现象：导航仅靠 `1px solid --mr-border` 下边框与内容分隔，滚动后没有任何阴影、背景模糊或加深效果。由于页面背景 `--mr-bg #f2f2f7` 与导航卡片 `#ffffff` 本身接近，滚动时导航与下方白色卡片内容容易"贴"在一起，用户滚动后位置感弱。
   - 建议：监听滚动位置，滚动超过 ~8px 后给 header 追加 `box-shadow: var(--mr-shadow)` 与 `backdrop-filter: blur(8px)` 的半透明背景，形成浮层感。

4. **[P2] 搜索入口用 emoji「🔍」而非 SVG 图标，与汉堡菜单的手绘 SVG 风格不统一**
   - 位置：桌面导航右侧「🔍 搜索」按钮、移动端面板内同款
   - 现象：导航里汉堡按钮是线性 SVG（stroke 1.8），而搜索按钮直接用彩色 emoji「🔍」，不同操作系统（Win/Android/iOS）渲染成完全不同的图形风格和颜色；同时该按钮固定 `height:32 / lineHeight:30px`，与相邻导航项的垂直节奏略有错位。
   - 建议：替换为与汉堡菜单同风格的线性 SVG 放大镜图标（stroke 一致、18×18），去掉 emoji；统一按钮高度与对齐基线。

5. **[P2] Logo 旁「模型榜」徽章圆角 2px，与全站圆角体系（卡片 8px / 按钮 4px）不一致**
   - 位置：导航左侧「ModelRank」文字后的蓝色小徽章
   - 现象：徽章 `borderRadius: 2`，而 `.mr-card` 是 8px、`.mr-btn-*` 是 4px、数据来源页卡片是 6px——全站至少出现 2/4/6/8 四种圆角，徽章这一处最小最突兀。
   - 建议：统一为 4px（与按钮一致），或直接采用 token 化的圆角变量，避免逐处硬编码。

### 【底部 Footer】

6. **[P1] Footer 链接无下划线、颜色过浅，与静态分隔符「·」无法区分**
   - 位置：Footer 左侧「方法论 · 数据来源 · 免责声明 · 关于」一行
   - 现象：四个链接均为 `textDecoration: "none"`、颜色 `--mr-text-3 (#86909c)`、字号 12px，与纯文本分隔符「 · 」用同一颜色同一字号呈现，视觉上完全没有"这是可点链接"的提示；且 #86909c 在白底上对比度约 2.9:1，低于 WCAG AA 对 12px 正文要求的 4.5:1。
   - 建议：Footer 链接默认加 1px 下划线或 hover 时出现下划线；常态颜色加深到 `--mr-text-2` 级别（对比度 ≥4.5:1）；hover 时变 `--mr-primary`。

7. **[P1] 全站没有任何 `:focus-visible` 焦点样式，键盘用户看不到焦点位置**
   - 位置：全局（Footer 链接、导航链接、搜索按钮、数据来源外链）
   - 现象：`globals.css` 中没有定义 `:focus` / `:focus-visible` 规则，lead-form 的输入框甚至显式写了 `outline: "none"` 且无替代焦点环。Tab 键遍历全站时，用户完全看不到当前焦点落在哪个元素上。
   - 建议：在 globals.css 增加统一的 `:focus-visible { outline: 2px solid var(--mr-primary); outline-offset: 2px; border-radius: 2px; }`，并为 `outline:none` 的输入框补一圈 focus 态边框。

8. **[P2] 共享 Footer 缺少联系方式与社交链接，跨页面信息不一致；也无"回到顶部"**
   - 位置：所有内页底部 Footer（vs 首页底部的「商务邮箱 / 微信 / GitHub」区块）
   - 现象：首页正文底部有商务邮箱 hi@modelrank.dev、微信 ModelRankBot、GitHub 仓库链接；但三个辅助页与其他内页的共享 Footer 只有 4 个文字链接 + 版权行，用户在 About 页想发邮件却找不到入口，必须回到首页。Footer 也没有"回到顶部"入口。
   - 建议：把邮箱 / GitHub / 微信收进全局 Footer（可放在版权行右侧或第三行），保证跨页面一致；Footer 右侧可加「回到顶部 ↑」链接。

9. **[P2] 版权年份硬编码为 © 2026，且站点无任何备案信息**
   - 位置：Footer 版权行「© 2026 ModelRank 模型榜 · 不构成采购建议」
   - 现象：年份写死在 JSX 里，明年起即过期；站点面向中文用户但 Footer 无 ICP 备案号 / 公网安备信息（当前托管在 Cloudflare Pages，若后续迁移国内节点会成为合规缺口）。
   - 建议：年份改为 `new Date().getFullYear()` 动态输出；若计划面向国内合规运营，Footer 预留备案号位（即使先空着），并在 about 页说明运营主体。

### 【返回顶部按钮 / Toast 通知】

10. **[P1] 全站没有返回顶部按钮**
    - 位置：全局（首页 26 行模型表格 + 完整榜单页 + 新闻页均为长滚动页面）
    - 现象：全仓库 grep 不到任何 BackToTop / scroll-to-top 组件。首页榜单表格 26 行、新闻列表较长，用户滚到页尾后想回顶部重新筛选，只能手动滚动长距离。
    - 建议：在 scrollY > 400 后于右下角（z-index 低于导航 40）淡入一个圆形「↑」按钮，点击平滑 `scrollTo({top:0, behavior:"smooth"})`，带 `aria-label="返回顶部"`。

11. **[P2] 无独立 Toast/通知体系，表单反馈仅靠按钮变色**
    - 位置：模型详情页「企业咨询留资」提交后的反馈
    - 现象：提交成功只把按钮文字从「提交咨询」改成绿色「已提交 ✓」，3 秒后自动复原；没有任何悬浮 Toast、成功/失败提示音或 aria-live 区域，读屏用户感知不到提交结果，失败态（如网络错误）更是无任何反馈。
    - 建议：封装一个全局 Toast 组件（成功绿色 / 失败红色，右上角或底部居中浮起，3s 自动消失），容器加 `role="status" aria-live="polite"`；提交后用 Toast 告知结果。

## 二、关于页（/about）

12. **[P1] 内容区横向 padding 硬编码 44px，未使用现成的响应式工具类，移动端左右留白过大**
    - 位置：About / 数据来源 / 免责声明三个页面的内容容器 `padding: "24px 44px 0 44px"`
    - 现象：globals.css 明明已经定义了 `.mr-pad-x`（移动端 16px / ≥768px 44px）和 `.mr-mx`，Footer 也正确用了 `.mr-mx`；但三个页面却写死了内联 `44px 44px`。在 375px 宽手机上，左右各吃掉 44px（共 88px），正文仅剩约 287px 宽，长文每行只能排 13 个汉字，阅读体验差，与导航栏移动端 16px 的左右边距也不对齐。
    - 建议：三个页面统一改用 `.mr-pad-x` 类（或 Tailwind `px-4 md:px-[44px]`），与导航、Footer 的响应式节奏对齐。

13. **[P1] 长文容器 maxWidth 未居中，宽屏时正文贴左、右侧大片空白**
    - 位置：About 与免责声明 `maxWidth: 760`、数据来源 `maxWidth: 820` 的内容容器
    - 现象：只设了 `maxWidth`，没有 `marginLeft: "auto", marginRight: "auto"`。在 1440px 桌面上，正文从左 44px 起排到 ~800px 就结束，右侧约 600px 全是背景色空白，多行正文被迫靠左对齐，视线从正文跳到右侧页脚链接的动线很差。
    - 建议：内容容器加 `margin: "0 auto"`，让长文块在桌面水平居中；移动端 16px padding 下自然顶满。

14. **[P2] 页面大标题用 `<div>` 而非 `<h1>`，整页无标题层级**
    - 位置：三个页面的「关于 ModelRank」「数据来源」「免责声明」标题行
    - 现象：标题是 `<div style={{fontSize:24, fontWeight:600}}>`，语义上就是个普通粗字块；页面内卡片小标题是 `<div fontSize:15>`，整篇没有 h1/h2 标签。搜索引擎与读屏软件无法按标题导航。
    - 建议：页头标题改为 `<h1>`，卡片区块标题改为 `<h2>`，样式（字号/字重/颜色）保持不变即可。

15. **[P2]「我们承诺：不接受付费排名」核心信任声明无视觉强调，与普通段落混排**
    - 位置：About 页卡片内第二段
    - 现象：这句全站最重要的信任承诺只比正文多了一个 `<b>` 加粗，没有左侧色条、浅色 callout 背景或图标，淹没在三段 1.9 倍行距的灰文字里。作为一个标榜"独立、透明"的榜单，这句是最该被一眼看到的内容。
    - 建议：给该段单独包一个左侧 3px 主色边条 + `--mr-primary-bg` 浅蓝底的 callout 块，或加一个盾牌/对勾图标。

## 三、数据来源页（/data-sources）

16. **[P1]「污染风险」徽章只做了一半的颜色编码：彩色底配灰字，且无图例**
    - 位置：五个 benchmark 卡片右侧的「污染风险：高/中/低」标签
    - 现象：徽章背景按高=红 12% / 中=琥珀 12% / 低=绿 12% 着色，但文字颜色统一是 `--mr-text-2` 灰色，不是对应色系的深色；页面上也没有任何图例说明红/黄/绿分别代表什么。用户看到一个浅红底灰字的小标签，无法直觉判断"高"是危险还是好事。
    - 建议：文字颜色同步加深（高用 `#c0392b`、中用 `#9a6a00`、低用 `#2e7d4f`），并在「Benchmark 基准」标题下加一行图例：🔴 高污染风险 / 🟡 中 / 🟢 低。

17. **[P2] 公开页面向普通用户暴露内部仓库文件路径**
    - 位置：「价格与产品信息」卡片第二段内联 code
    - 现象：正文里直接写着"采集后在本仓库 `apps/web/src/lib/seed-data.ts` 中维护"——这是给开发者看的实现细节，普通读者既打不开也不需要知道；对外信息页出现源码路径显得像 demo 未打磨。
    - 建议：改为"采集后由我们在内部数据仓库中统一维护"，路径信息只放在 GitHub README 里。

18. **[P2] 兄弟信息页内容宽度不统一（760 / 820）**
    - 位置：About、免责声明 maxWidth 760；数据来源 maxWidth 820
    - 现象：三个从 Footer 进入的辅助信息页，正文容器宽度却有两档，用户从 About 跳到数据来源时会感觉到版面宽度跳变，且 820px 已接近舒适行长（约 55-75 汉字行）上限的边缘。
    - 建议：统一为同一 maxWidth（建议 720-760），卡片列表页如需更宽，用栅格而非放大正文容器。

## 四、免责声明页（/disclaimer）

19. **[P1] 法律文案中混入英文单词「respective」，中英混杂**
    - 位置：免责声明第三段「文中出现的 GPT、Claude……均为其 respective 权利人的商标或商号」
    - 现象：整段是正式中文法律文本，突然插入一个英文单词 respective（"各自的/相应的"），属于明显的文案遗留错误；法律声明对措辞严谨度要求最高，这种混排会让用户质疑站点的专业度。
    - 建议：改为「均为其**各自**权利人的商标或商号」；发布前对法律文本做一次中英混排与错别字专项校对。

20. **[P2] 免责声明页缺少副标题行，页头结构与兄弟页不一致**
    - 位置：免责声明页大标题下方
    - 现象：About 页大标题下有灰色副标题「独立、透明、可申诉的大模型能力排行榜」，数据来源页有「所有榜单分数均可追溯到下列公开来源」；唯独免责声明只有孤零零一个 24px 大标题，下面直接接卡片，页头节奏比另两页"短一截"。
    - 建议：补一句副标题，如「信息仅供参考，最终以厂商官方文档为准」，三页页头结构对齐。

## 五、全站 Meta / 品牌

21. **[P2] `metadataBase` 指向旧域名 workers.dev，与实际部署域名 pages.dev 不一致**
    - 位置：`app/layout.tsx` 第 7 行 `metadataBase: new URL("https://modelrank.zheng-cool.workers.dev")`
    - 现象：站点实际部署在 `modelrank-1br.pages.dev`，但 Open Graph / Twitter Card / canonical 相关元数据的基准域名仍指向另一个 workers.dev 域名。用户在微信/Twitter 分享本站链接时，抓取到的 OG 图片与链接会指向旧域名，属于品牌资产外流。
    - 建议：把 `metadataBase` 改为当前正式域名（或抽成环境变量 `NEXT_PUBLIC_SITE_URL`），部署后用分享调试工具验证一次卡片抓取。
