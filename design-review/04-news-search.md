## 一、新闻页 `/news`

### 1. **[P1] 「相关：xxx」标签视觉上像链接，实际不可点，点击整卡只会跳站外**
- 位置：每张新闻卡片底部信息行中部的蓝色徽章（如「相关：Claude Opus 4.5」）
- 现象：该 badge 使用品牌蓝底（`--mr-primary-bg` + `--mr-primary`），与全站其他可点标签样式完全一致，用户直觉会点击它跳转模型详情；但它在代码里只是一个 `<span>`（`news/page.tsx:94`），整卡才是一个 `target="_blank"` 的外链锚点。用户想从新闻跳到站内模型页时，会被带去第三方网站。
- 建议：把「相关：{model}」改成真正的 `<Link href="/detail/[id]">`，并阻止冒泡（`e.preventDefault` + 跳站内路由）；或至少改成纯灰色普通文字样式，去掉可点伪装。

### 2. **[P1] 标题与摘要均无行数截断规则，长内容会撑乱卡片高度**
- 位置：新闻卡片正文区（`news/page.tsx:87-90`）
- 现象：标题 `fontSize:15`、摘要 `fontSize:12`，两行都没有 `-webkit-line-clamp` / `overflow:hidden` / `text-overflow:ellipsis`。目前种子数据每条摘要只有一句话所以看不出问题，但一旦接入真实 RSS 长摘要，卡片高度会参差不齐，双列网格底部对不齐；且没有「展开全文」入口。
- 建议：标题限 2 行、摘要限 2–3 行截断（`display:-webkit-box; -webkit-line-clamp:2`），行高统一；摘要过长时提供「展开」按钮或直接以卡片为入口跳转原文。

### 3. **[P1] 时间为写死的相对时间字符串，无绝对日期、无 tooltip；列表无分页/归档**
- 位置：卡片底部「来源 · 时间」（如「Anthropic · 2 小时前」）
- 现象：时间文案是硬编码（seed-data 中 `"2 小时前"`、`"昨天"`、`"上周"`），页面部署后这些相对时间会永远失真——下周再看仍是「2 小时前」。同时页面只有 6 条硬编码新闻，没有「加载更多」「分页」「历史归档」入口，用户无法看到更早的资讯。
- 建议：改用真实时间戳 + 前端相对化（24h 内显示「x 小时前」，超出显示 `2026-10-25` 绝对日期），hover 时 tooltip 显示完整 ISO 时间；列表底部加「加载更多 / 查看全部 N 条」。

### 4. **[P1] 摘要与元信息用 `--mr-text-3`（#86909c），浅色模式对比度仅约 3.2:1，不达 WCAG AA**
- 位置：所有新闻卡片的摘要行、来源/时间行（`color: var(--mr-text-3)`）
- 现象：`#86909c` 白底上对比度约 3.2:1，而摘要字号只有 12px（非大号文本），WCAG AA 要求 4.5:1。老年人与户外强光环境下摘要几乎看不清。暗色模式下因底色加深反而约 5.2:1 通过，问题集中在浅色模式。
- 建议：摘要与元信息在浅色模式改用 `--mr-text-2`（#4e5969，对比度约 7:1），或把 `--mr-text-3` 整体加深到 #6b7382 附近；仅占位/弱化提示可用 text-3。

### 5. **[P1] 分类筛选按钮无键盘焦点样式，激活态阴影色硬编码不适配暗色模式**
- 位置：「全部 / 发布 / 评测 / 融资 / 政策 / 价格」分段控件（`news/page.tsx:38-56`）
- 现象：按钮 `border:"none"` 且全局 `outline` 未保留，源码里没有任何 `:focus-visible` 样式——键盘 Tab 用户完全看不到自己停在哪个分类上。另外激活态阴影写死 `0 1px 3px rgba(29,33,41,0.12)`，暗色模式下深灰投影打在深色卡片上不可见，等于激活态只剩文字变色，反馈弱。
- 建议：为按钮补 `:focus-visible { outline: 2px solid var(--mr-primary); outline-offset: 2px }`；激活阴影改用 `var(--mr-shadow)` 或带透明度的通用 token，随暗色模式自动切换。

### 6. **[P2] 每张卡片都重复挂「AI 摘要」灰色标签，属于无信息增量的装饰噪音**
- 位置：卡片顶部标签行，分类 badge 右侧
- 现象：6 张卡片无一例外都有一个同样式的灰底「AI 摘要」badge。它传达的信息是「本列表全部条目均为 AI 摘要」，应该放在页面副标题或列表头部说明一次，而不是每张卡片重复一次——重复后视觉权重被稀释，用户反而分不清它和「发布/价格」等有意义分类的区别。
- 建议：删除卡片内的「AI 摘要」badge，改在页面副标题「发布 · 评测 · …」后加一句小字「列表由 AI 摘要生成」；若要保留，可做成极小的角标（如卡片右上角 16px 图标 + title 提示）。

### 7. **[P2] 卡片双列 `maxWidth:434px` 写死，宽屏右侧留大块空白，断点区间单列浪费**
- 位置：新闻卡片网格（`flex:1 1 100%; maxWidth:434`）
- 现象：桌面容器宽约 1100px+，434×2+16=884px，右侧空出约 200px；6 条数据排成 3 行，最后一行只剩 1 张卡片左对齐，右侧整行空白。而在 768–884px 区间（平板）两列放不下（884>可用宽），只能单列，卡片被拉满宽、阅读行过长。
- 建议：改为响应式网格 `repeat(auto-fill, minmax(340px, 1fr))`，宽屏自动 3 列、平板 2 列、手机 1 列；末行单卡时保持网格对齐而非拉伸。

### 8. **[P2] 空状态仅一行灰字，无插画、无「清除筛选」恢复路径**
- 位置：分类筛选后无结果时的渲染（`news/page.tsx:102-104`）
- 现象：显示「该分类暂无新闻」纯文字，垂直 padding 仅 20px，没有空状态插画、没有说明为什么空、也没有一键回到「全部」的按钮。当前种子数据每个分类都有数据，该状态实际触发不到，等于未设计。
- 建议：补一个轻量空状态（简约图标 + 「该分类暂时没有新动态」+ 「查看全部新闻 →」链接），与搜索页空状态框视觉统一。

### 9. **[P2] 来源与时间挤在一个「·」分隔串里；来源不可点、无媒体标识；「站外 ↗」无辅助说明**
- 位置：卡片底部左侧 `{n.source} · {n.time}` 与最右侧「站外 ↗」
- 现象：「机器之心 · 5 小时前」把媒体名和时间压在同一字号同一颜色里，用户要靠「·」自行断句；媒体既无 favicon/logo 也不可点击（无法看该媒体更多新闻）。「站外 ↗」是纯文字蓝色，整卡又是新窗口外链，但没有 `aria-label`，读屏器只会念「站外」。另外站内没有新闻详情页，用户无法原地阅读。
- 建议：来源与时间分两行或用不同灰度（来源 text-2、时间 text-3）；来源前加 16px 媒体 logo；外链文字加 `aria-label="阅读原文（新窗口打开）"`；中期补站内新闻详情页。

### 10. **[P2] 页面副标题与分类 tabs 文案完全重复；移动端 tabs 不换行小屏有溢出风险**
- 位置：标题区副标题「发布 · 评测 · 融资 · 政策 · 价格」与其下方 6 个分类按钮
- 现象：副标题把 6 个分类名原样罗列了一遍，紧接的 tabs 又是同样 6 项，信息重复。另外 tabs 容器是 `inline-flex` 不换行，375px 窄屏下 6 个「padding 6px 16px」按钮合计约 360px，接近可用宽 343px，极限小屏会溢出且没有 `overflow-x:auto` 兜底。
- 建议：副标题改为一句价值说明（如「每日更新大模型发布、评测、融资与政策动态」），分类名只在 tabs 出现；tabs 容器加 `overflow-x:auto; -webkit-overflow-scrolling:touch`，并隐藏横向滚动条。

## 二、搜索页 `/search`

### 11. **[P1] 搜索框常态就是蓝色边框 + 蓝色光晕，看起来永远处于聚焦态；同时 `outline:none` 导致键盘焦点反而不可见**
- 位置：搜索输入框（`search/page.tsx:69-81`）
- 现象：输入框把 `border:1px solid var(--mr-primary)` 和 `boxShadow:0 0 0 2px rgba(42,92,170,0.12)` 写死在默认样式里——页面刚打开、框未聚焦时它就已经是「高亮蓝框」，用户分不清自己是否真的在输入；而代码又 `outline:"none"`，真正用 Tab 键盘聚焦时反而没有任何额外焦点环。常态样式与聚焦样式完全颠倒。
- 建议：常态用 `1px solid var(--mr-border)`，`:focus` 时再加蓝边框 + 2px 光晕；保留 `:focus-visible` 焦点环。

### 12. **[P1] `autoFocus` 自动抢焦点，且 input 无 aria-label，仅靠 placeholder 暴露用途**
- 位置：搜索输入框（`search/page.tsx:61-68`）
- 现象：页面一加载输入框就自动聚焦，打开页面瞬间页面被滚到输入框、屏幕阅读器立刻开始念 placeholder，跳过了面包屑与页面标题。input 本身没有 `aria-label`/`aria-labelledby`，只读屏用户只听到「输入模型名、厂商…」而不知道这是「全站搜索框」。
- 建议：去掉 `autoFocus`（或仅在 URL 带 `?q=` 时保留）；给 input 加 `aria-label="全站搜索模型与新闻"`，并补 `role="search"` 包裹。

### 13. **[P1] 搜索结果完全没有关键词高亮，用户无法判断命中位置**
- 位置：模型结果行名称、新闻结果行标题（实测 `/search?q=deepseek`）
- 现象：输入「deepseek」后，结果里的「DeepSeek-R1」「DeepSeek-V3」「DeepSeek-R1 盲测…」字样都是普通文本，没有任何 `<mark>` 高亮。搜索框输入即实时过滤，但结果区没有视觉锚点，用户要自己逐行扫读确认命中词。
- 建议：对命中的 name/vendor/title/summary 子串包 `<mark>`（用 `--mr-warn-bg` 或 primary-bg 高亮），新闻结果同时展示摘要命中片段（高亮命中句）。

### 14. **[P1] 无实时建议下拉、无搜索历史/热门词、无一键清空按钮**
- 位置：搜索输入框及其下方区域
- 现象：输入时只有页面下方结果区变化，没有任何下拉建议（模型名前缀补全都没有）；空状态框只静态列了「GPT/开源/价格」三个例子，不记录用户真实搜索历史；输入框内也没有「×」清空按钮，想换词必须手动全选删除。导航栏甚至没有 ⌘K 快捷入口。
- 建议：输入后显示最多 6 条前缀匹配的模型名下拉（键盘 ↑↓ 可选）；空状态增加「最近搜索」chip；input 右侧加清空按钮；桌面端支持 `/` 或 ⌘K 快速聚焦。

### 15. **[P1] 结果行用固定宽度列布局，移动端窄屏溢出，长标题无省略号**
- 位置：模型结果行（score 列 `width:160` + price 列 `width:160`）与新闻结果行（category 列 `width:80` + meta 列 `width:180`）
- 现象：模型行固定列宽合计 36+12+160+160≈368px，375px 手机扣除 32px 边距只剩 343px，价格列必然被挤出屏幕；新闻行固定 80+180=260px，标题列只剩几十像素，而代码没有 `min-width:0`、没有 `overflow:hidden`、没有 `text-overflow:ellipsis`——长标题（如「第三方评测：DeepSeek-R1 盲测胜率升至 58%」）会直接撑破 flex 行或被裁切无提示。
- 建议：移动端改为纵向堆叠（名称行 + 次要信息行 flex-wrap），桌面端再用两列；所有弹性文本列补 `min-width:0` + `ellipsis`；价格/分数列加 `shrink:0` 防压缩。

### 16. **[P1] 新闻结果只展示标题，不展示命中的摘要片段**
- 位置：搜索结果「新闻（n）」分区
- 现象：搜索逻辑明明匹配了 `n.summary` 字段（`search/page.tsx:46`），但结果行只渲染标题 + 分类 badge + 来源时间，摘要一个字都不显示。用户搜「备案」「价格下调」这类出现在摘要而非标题里的词时，看到标题与关键词无关，会误以为没搜到。
- 建议：新闻结果改为两行结构（标题行 + 摘要命中片段行，高亮关键词），与新闻页卡片信息层级对齐。

### 17. **[P2] 零结果时两个分区各自提示，无统一空状态；只命中一类时另一类空分区仍占位**
- 位置：模型/新闻两个结果卡片内的空态文案
- 现象：输入一个两边都不命中的词，会先看到「模型（0）」标题 + 「未找到相关模型」卡片，再看到「新闻（0）」标题 + 「未找到相关新闻」卡片，两条灰色提示割裂；且没有「未找到与「xxx」相关的内容」统一结论，也没有「换个关键词试试 / 查看全量模型库」的出口。只命中模型时，新闻空卡片仍占一屏高度。
- 建议：仅当某分区有结果时才渲染分区标题与列表；全部为空时显示统一空状态（插画 + 「没有找到与「q」相关的模型和新闻」+ 推荐词 chips）。

### 18. **[P2] 无模型/新闻分类 Tab 与结果总数汇总；两类结果跳转行为不一致**
- 位置：搜索结果区标题行「模型（n）」「新闻（n）」
- 现象：标题只有分区块计数，页面没有「共 N 条结果」的汇总，也没有「全部 / 模型 / 新闻」Tab 切换——结果一多就只能长滚动。另外模型结果行整行跳站内 `/detail/[id]`，新闻结果行却 `target="_blank"` 跳第三方外链，用户点两类结果的预期（站内详情 vs 站外原文）没有任何视觉区分（新闻行尾部的「站外 ↗」字太小）。
- 建议：顶部加一行「共 N 个模型 · M 条新闻」；可选 Tab 过滤；新闻行的「↗」前加「新窗口」小字或统一用外链图标组件。

### 19. **[P2] 导航「🔍 搜索」用 emoji 字符按钮，与全站 SVG 图标体系不一致，且手机端藏在汉堡菜单里**
- 位置：顶部导航右侧「🔍 搜索」按钮（`nav-header.tsx:116`）
- 现象：图标直接用 emoji「🔍」，而汉堡菜单用的是手写 SVG path——两套图标风格，emoji 在不同系统字体下渲染大小/颜色都不可控（会带彩色，与品牌蓝不搭）。移动端这个入口被折叠进汉堡菜单二级面板，想搜索要先点汉堡再点搜索，路径偏长。
- 建议：换统一尺寸/描边的 SVG 搜索图标（与汉堡菜单同款 stroke）；移动端导航栏直接放一个图标按钮直达 `/search`，不必进菜单。

### 20. **[P2] 输入框触控高度仅 32px 偏小；「搜索」按钮在即时过滤下冗余；引导文案三处重复**
- 位置：搜索框行（`height:32`）与页面文案
- 现象：输入框和按钮都是 32px 高，低于移动端 44px 触控建议。由于输入即实时过滤，「搜索」按钮和 Enter 键只做一次 `router.replace` 同 URL，功能为空操作。文案上，副标题「按模型名、厂商、关键词全站检索」、placeholder「输入模型名 / 厂商，如 GPT、DeepSeek、开源…」、空状态「试试「GPT」「开源」「价格」」三处反复解释同一件事。
- 建议：输入框高度提到 40px+（按钮同高）；保留按钮做提交语义即可，但 Enter/按钮可加「搜索后滚动到结果」行为；三处引导只保留 placeholder 示例词，副标题改为一句结果口径说明（如「覆盖 26 个模型与最新动态」）。
