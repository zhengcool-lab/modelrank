# ModelRank 模型榜 —— 模型库 / 对比器 设计评审

- **评审日期**：2026-10-28
- **评审页面**：
  - 模型库：https://modelrank-1br.pages.dev/library
  - 对比器：https://modelrank-1br.pages.dev/compare
- **评审方式**：浏览器实际渲染截图（桌面 1800px 视口）+ 静态 HTML/CSS 源码分析 + 交互走查（首页勾选 3 个模型后进入对比横表）
- **问题总数**：20（P0 × 2，P1 × 11，P2 × 7）

> 设计系统基线（取自站点 CSS 变量）：主色 `--mr-primary:#2a5caa`，强调橙 `--mr-orange:#ff6b35`，背景 `#f2f2f7`，正文基础字号 13px，卡片圆角 8px，按钮圆角 4px。下文引用这些变量作为对照。

---

## 一、模型库（/library）

### 1. **[P0] 模型总数自相矛盾：副标题写"128 个"，分页写"共 25 个"**
- **位置**：页面标题副标题行 vs 表格底部分页栏
- **现象**：副标题为"全量 128 个模型 · 按综合分排序"，但表格底部却显示"第 1–10 条 / 共 25 个模型"，分页器只有 `上一页 1 2 3 下一页`（3 页 × 10 条 ≈ 25 条）。两处数字差 5 倍，用户无法判断库里到底有多少模型，也直接动摇"全量"这一数据可信度承诺。
- **建议**：统一两处数据源；若实际仅 25 条，把副标题改为"共 25 个模型"；若确为 128 条，分页需补全到 13 页，并在副标题与分页间共用同一个 count 变量。

### 2. **[P1] 表格行无斑马纹，行分隔线几乎不可见，长列表易串行**
- **位置**：模型列表表格 tbody 各行
- **现象**：行底使用 `--mr-border-soft:#f2f3f5`（与页面背景同色），行高 56px、纯白底，10 行数据之间只有一条几乎看不见的极浅线；无斑马纹、无 hover 整行高亮。横向跨"排名—模型—评分—价格—性价比"五列扫视时，眼睛容易串行到下一行。
- **建议**：奇偶行交替极浅灰底（如 `--mr-card-2`），或把行分隔线加深为 `--mr-border:#e5e6eb`；同时给 `tr:hover` 加 `background:var(--mr-primary-bg)` 反馈。

### 3. **[P1] 数值列全部左对齐，评分/价格无法纵向对齐比较**
- **位置**：评分列（96.3 / 0.8 / 87.5）、价格列（12 / 60、0.8 / 2.4）
- **现象**：所有数值单元格左对齐（固定列宽 + 默认左对齐）。评分位数不一（一位小数 vs 两位小数）、价格 `0.8 / 2.4` 与 `12 / 60` 位数差异大，左对齐后小数点和个位不对齐，用户纵向比"谁更便宜/谁分更高"时要靠眼睛逐个数位对位。
- **建议**：评分、价格、性价比等纯数值列改为等宽数字字体 + 右对齐（或小数点对齐），并把 ±CI 小字与主评分做基线对齐，形成"数值列一眼可比"。

### 4. **[P1] 移动端横向滚动无任何引导：列宽写死 910px，小屏被迫横滚但不冻结首列**
- **位置**：表格容器（`overflow-x:auto`，列宽写死：排名 70 + 模型 320 + 评分 180 + 价格 220 + 性价比 120）
- **现象**：桌面端靠 `overflow-x:auto` 兜底，375px 手机必然横向滚动。但：① 无冻结首列/首列（滚动后排名与模型名一起滚走，对不上数据）；② 无右侧渐变阴影或"← 左右滑动 →"提示；③ 表头行随内容一起滚走。用户在手机上看完价格列就忘了是哪个模型。
- **建议**：小屏把表格降级为"卡片列表"（每行一张卡，模型名/评分/价格纵向堆叠），或保留横滚但冻结"排名+模型名"两列并加滚动边缘渐变提示。

### 5. **[P1] 筛选维度过于单薄：只有"厂商"一个维度，15 个 chip 平铺，无价格/能力/开源筛选与排序切换**
- **位置**：标题下方"厂商分组"一排 chips（全部/OpenAI/Anthropic/Google/深度求索/阿里/Meta/Mistral/腾讯/阶跃星辰/MiniMax/零一万物/智谱/百川/Microsoft）
- **现象**：① 筛选器只有厂商一个维度，缺少价格区间、开源/闭源、能力（推理/代码/中文）、性价比等级等榜单用户真正会用的切面；② 副标题写"按综合分排序"却没有排序切换控件，用户无法改按价格/速率排序；③ 15 个 chip 在 768–1024px 区间换行后长短不一、对齐凌乱；④ 页内没有搜索框，想找具体模型名必须跳到顶部全局搜索页。
- **建议**：把筛选区升级为分组筛选栏（厂商 / 价格区间 / 开源闭源 / 性价比等级），加排序下拉（综合分/价格/速率），并在页内放一个搜索框；厂商 chip 区在中屏改为可横向滑动的单行，避免凌乱换行。

### 6. **[P1] 圆角与控件高度体系混乱：2 / 4 / 6 / 8 四种圆角、28 / 32 / 36px 三种高度并存**
- **位置**：全站组件对照
- **现象**：卡片圆角 8px、按钮 4px、Logo 旁"模型榜"小标签圆角 2px、性价比徽章圆角 2px、厂商 chip 高 28px、顶栏搜索框/按钮高 32px、深色切换按钮 36×36px、`.mr-btn-orange` 高 36px 而 `.mr-btn-primary` 高 32px。同一屏内相近控件高度差 4–8px、圆角差 4–6px，视觉上显得"凑出来的"而非统一设计系统。
- **建议**：定一套 token：圆角 `--radius-sm:4 / --radius-md:6 / --radius-lg:8`，控件高度统一 `--control-h:32`（小尺寸 28 仅用于 chip 组），橙色按钮与主按钮同高。

### 7. **[P2] 排名奖牌色对比度不足：银牌 `#c0c0c8` 在浅灰背景上几乎隐形**
- **位置**：排名列第 1/2/3 名（金 `#e8b339` / 银 `#c0c0c8` / 铜 `#cd7f32`）
- **现象**：金牌尚可辨认，但银牌 `#c0c0c8` 是极浅冷灰，与 `--mr-text-3:#86909c` 灰字接近，在 `#f2f2f7` 背景上辨识度很低；铜牌偏棕也偏暗。前三名本应是视觉焦点，结果第 2、3 名排名数字发灰发飘。
- **建议**：银牌加深为 `#8a919e` 或改为带浅底的奖牌徽章（灰底白字），铜牌用更饱和的橙棕；或前三名统一用品牌色深浅阶区分，而非写实金属色。

### 8. **[P2] 性价比 C 级徽章对比度差，几乎读不出**
- **位置**：性价比列徽章（S 深蓝 / A 蓝 / B 灰 / C 极浅灰）
- **现象**：C 级徽章是浅灰底 + 浅灰字（截图中第 9 名 Llama 4 Maverick 的 C 徽章几乎与卡片背景融为一体），WCAG 对比度明显不足；B 徽章灰底白字也偏闷。S/A 是实色底白字，B/C 却退成灰阶，四级之间视觉跳变不连续。
- **建议**：S/A/B/C 四级统一用"色相递进"（如 S 深蓝、A 蓝、B 青、C 灰），每级保证文字与底色对比度 ≥ 4.5:1；C 级至少用中灰底白字而非浅灰底浅灰字。

### 9. **[P2] 模型库每行没有"加入对比"入口，与首页/榜单页组件不一致**
- **位置**：表格最右"操作"列（只有"查看详情"链接）
- **现象**：首页/榜单页每行都有"对比 XXX"按钮，但模型库每行操作列只有一个"查看详情"文字链接。用户在模型库（本就是为浏览/筛选模型设计的页面）看中一个模型想加入对比，却找不到入口，必须退回首页勾选——两个页面组件能力不对齐。
- **建议**：在模型库操作列加"对比"小按钮（或在每行加一个空状态复选框），与首页"对比 XXX"按钮复用同一组件，点击后进入对比器。

### 10. **[P2] 表格内左右 padding（24px）与页面容器（桌面 44px）不对齐**
- **位置**：表格卡片内部 vs 页面标题区
- **现象**：页面内容边距用 `.mr-mx`（桌面 44px），但表格行内 `padding:0 24px`，导致表格里的"排名/模型"文字比上方"模型库"标题向内缩进了 20px，左右基线对不齐；表头行背景块也比卡片可视区多出一截内缩。
- **建议**：表格行内 padding 与页面容器统一（桌面 44px 或表格卡片内部单独定义一套对称 padding），让表头、数据行、分页栏左右对齐到同一条竖线。

## 二、对比器（/compare）

### 11. **[P0] 空状态引导断链：让用户"从首页勾选"，但导航里没有"首页"，页面本身也没有添加按钮**
- **位置**：空状态虚线框"空选择态：尚未选择模型——从首页勾选 2–4 个模型后，此处出现对比横表"
- **现象**：① 顶部导航第一项叫"榜单"不叫"首页"，文案里的"首页"是死链概念；② 对比器页面自身没有任何"添加模型"按钮/搜索框；③ 模型库也没有对比入口（见问题 9）。用户被指引去一个不存在的入口，空状态实际阻断了"第一次使用"。
- **建议**：空状态虚线框内嵌一个主按钮"去模型库挑选模型"（跳 /library 并带勾选态），并在对比器常驻一个"+ 添加模型"下拉搜索；把文案"从首页勾选"改为准确的"从模型库勾选"。

### 12. **[P1] 对比横表不高亮每行最优值，丧失对比器核心价值**
- **位置**：多模型对比横表（综合评分 / 速率 / 上下文窗口 / 价格各行）
- **现象**：两列数据并列展示，但每一行的最优值（最高分、最低价格、最大上下文窗口）没有任何加粗、着色或"Best"标记。用户要逐格自己比"94.1 vs 93.8 谁高""200K vs 1M 谁大"，对比器退化成了普通表格罗列。
- **建议**：每行最优值自动加粗 + 品牌色/绿色高亮，最差值用灰字弱化；或在每最优单元格加一个小"★"标记，让"一眼看出谁该选"成为对比器的核心卖点。

### 13. **[P1] "能力"行的进度条无图例、无数值、无标签，完全不可解读**
- **位置**：横表"能力（推理/代码/中文/多模态）"行
- **现象**：该单元格里画了 3–4 条长短不一的蓝色横条，但：① 每条横条不对应任何文字标签（推理/代码/中文/多模态分别哪条？）；② 横条末端不标数值；③ 不同模型之间横条数量还不一致。用户只能看到"几条蓝条长短不同"，无法知道差异意味着什么。
- **建议**：要么把能力维度拆成独立行（推理 X.X / 代码 X.X / 中文 X.X 各一行带数值），要么在进度条旁加图例和具体分值；不要用"无标签的装饰性横条"充当数据可视化。

### 14. **[P1] 列宽失衡：模型列后右侧留大片空白，同时"指标"列过窄导致标签换行成 2–3 行**
- **位置**：对比横表整体布局
- **现象**：加入 2 个模型时，两列模型只占了横表约 60% 宽度，右侧剩约 40% 完全空白（截图可见）；而左侧"指标"列被压得很窄，"能力（推理/代码/中文/多模态）""价格（输入/输出 ¥/M token）"这些标签被迫折成 2–3 行，行高被撑得很大、内容稀疏。模型列不撑满、指标列挤换行，两头都不对。
- **建议**：指标列固定一个合理宽度（如 140–160px，允许标签单行/两行内排），剩余空间由模型列等分撑满；模型列最少宽度设下限，避免 1–2 个模型时右侧大片留白。

### 15. **[P1] 橙色 CTA 与品牌蓝冲突，橙色语义混乱**
- **位置**："重新计算"全宽橙色按钮 + 推荐卡"查看详情"橙色按钮
- **现象**：主品牌色是深蓝 `#2a5caa`，但对比页"重新计算"是通栏亮橙 `#ff6b35` 按钮、推荐卡"查看详情"也是橙色；同时橙色还被用作模型库排名的强调色。一个页面里橙色既是 CTA 主按钮、又是推荐操作、又和主蓝按钮竞争视觉重心，用户分不清哪个才是"主操作"。
- **建议**：全站点只保留一个主操作色（建议品牌蓝 `--mr-primary`），橙色降级为"高亮/提醒"专用色（如环比上升、关键数据点），不要让橙色按钮与蓝色按钮同屏竞争主 CTA 地位。

### 16. **[P1] 三张推荐卡片风格不统一：一张深蓝实心卡，两张白底卡，视觉重量悬殊**
- **位置**：对比器底部"综合最强 / 性价比最高 / 预算内推荐"三卡片
- **现象**：左卡"综合最强 GPT-5"是深蓝底白字实心大卡（视觉极重），中间"性价比最高 Yi-1.5-9B"和右卡"预算内推荐 GPT-5"是白底卡。三张等高并排，第一张像"重点推荐"被硬塞进一排，与另两张不是一个组件族；右卡还带橙色按钮、中卡不带，卡片内部结构也不统一。
- **建议**：三张推荐卡复用同一白底卡片组件，用顶部小标签（"综合最强/性价比最高/预算内推荐"）区分，避免一张实心深蓝卡破坏卡片阵列的节奏；卡内按钮样式统一。

### 17. **[P1] 对比器主区 padding 写死 `24px 44px`，无移动端降级，小屏内容被挤**
- **位置**：对比器主体容器内联样式 `padding:24px 44px`
- **现象**：该 44px 是内联写死的，没有移动端 media query 覆盖；而模型库用的是响应式 `.mr-mx`（移动 16px / 桌面 44px）。在 375px 手机上，对比器左右各吃掉 44px，预算表单和对比表被挤在中间窄条里，两页面对小屏的适配策略不一致。
- **建议**：改用与模型库一致的响应式边距（移动 16px → 桌面 44px），不要在对比器单独写死 44px；并在小屏让"月预算"卡与"对比横表"改为上下堆叠而非左右并排。

### 18. **[P2] 表头模型名旁红色 × 直接移除列，无 hover 反馈、无确认、无撤销**
- **位置**：对比横表表头"GPT-5 × / Claude Opus 4.5 ×"
- **现象**：每个模型列右上角一个红色 ×，点击即移除该列；但 × 无 hover 变色/ tooltip 提示"移除后需重新添加"，误触即丢一列，且无 toast/撤销机会。对比列本身是用户精心挑选的，误删成本不低。
- **建议**：× 加 hover 态（变红/变深 + tooltip"移除该模型"），移除后出一个轻量 toast"已移除 GPT-5 · 撤销"，给 5 秒反悔窗口。

### 19. **[P2] 综合评分旁环比箭头语义不明，无图例、易与 ±CI 混淆**
- **位置**：横表"综合评分"行（96.3 ↑2.1 绿 / 94.1 ↓1.3 橙 / 93.8 — 灰）
- **现象**：绿色 ↑2.1、橙色 ↓1.3、灰色 — 三种状态，但页面上没有任何图例说明这是"周环比""月环比"还是"较上期"；同时模型库表格里评分旁边还有 `±2.1` 置信区间（CI），同样是"评分后面跟一个小数"，用户极易把环比箭头数字和 CI 混淆。
- **建议**：在横表表头或评分行加一个小图例"↑ 周环比变化"，并把环比箭头与 ±CI 在视觉上明确区分（环比放评分下方小字、CI 放括号里灰色），避免两个小数打架。

### 20. **[P2] 对比器首屏 SSR 只输出"加载中…"，无骨架屏，弱网下白屏感强**
- **位置**：对比器页面直出 HTML 主体
- **现象**：查看页面源码，对比器服务端直出的主体文字只有"加载中…"，横表/预算表单全部依赖客户端 hydration 后才渲染。弱网或 JS 加载慢时，用户在标题下方长时间看到一个孤零零的"加载中…"，没有骨架屏/占位卡片预判布局。
- **建议**：为对比器做服务端骨架屏（空状态卡片 + 预算表单占位 + 横表骨架），让首屏就有结构感；即使数据未到，也先渲染空状态虚线框而非一行"加载中…"。

## 附：两页面共性问题小结

| 维度 | 主要问题 |
|---|---|
| 数据一致性 | 模型库总数 128 vs 25 矛盾；环比箭头与 ±CI 混淆 |
| 视觉系统 | 圆角 2/4/6/8、高度 28/32/36 混用；橙蓝两色争夺主 CTA |
| 响应式 | 对比器 padding 写死 44px；模型库表格横滚无冻结/无提示 |
| 组件一致性 | 模型库无对比入口 vs 首页有；推荐卡深蓝实心 vs 白底；对比表无模型 logo vs 模型库有 |
| 空状态/首屏 | 对比器空状态引导断链；SSR 仅"加载中…"无骨架屏 |
| 可读性 | 数值列左对齐；C 徽章/银牌对比度不足；body 13px 偏小 |
