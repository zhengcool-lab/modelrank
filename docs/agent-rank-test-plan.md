## 一、怎么测：五个维度，五种验证手段

Agent 榜不同于模型榜。模型榜的分数来自单一权威源（Artificial Analysis），可以对数值；Agent 榜有三类**不同性质**的主张，混在一起测就会测不出问题：

| 页面主张 | 性质 | 对应验证手段 | 不能用的手段 |
|---|---|---|---|
| 套餐价格、倍率数值 | **客观事实** | 官方页面逐条对照，抓原文 | 看代码里写得顺不顺眼 |
| 能力等级 S/A/B/C | **编辑判断** | 检查"依据是否写明 + 依据本身是否可点开" | 找一个"正确答案"去比对 |
| 可调用最强模型及分数 | **客观事实 + 归属判断** | 分数对站内真实数据；归属查官方支持列表 | 只对分数不对归属 |

由此派生五层测试：

- **L1 数据准确层（D）**：官方定价页 ↔ 数据文件 ↔ 线上渲染值，三方一致才算过。渲染值必须从线上 HTML 回读，不信本地。
- **L2 可考性层（S）**：每条主张都要能点到底。等级要有依据句，依据句要有出处，出处要能打开，页面要有口径说明页承接。
- **L3 视觉层（V）**：三态（桌面 / 移动 / 暗色）× 两类页面（列表 / 详情），查对齐、断层、溢出、对比度。
- **L4 交互层（I）**：路由、404、导航态、跨端信息一致性、深链可分享。
- **L5 工程层（E）**：构建、SEO（sitemap/robots/canonical）、来源可达性、巡检覆盖。

## 二、用例清单

### L1 数据准确（D）

| ID | 用例 | 怎么测 | 判定标准 | 首轮结果 |
|---|---|---|---|---|
| D01 | 价格金额与官方页一致 | 打开 `sources` 第一条官方定价页，逐档比对 `plans[].monthly/promo` | 金额、币种、周期、席位全部一致 | 40 档抽查 10 档通过 |
| D02 | 促销价与原价成对出现 | 查 `promo` 字段是否都配了原价文案 | 有促销必标原价，不出现"¥45/月"却不说原价 | 通过 |
| D03 | 零价档语义正确 | 遍历 `monthly === 0` 的档，检查 note 是否表明"免费"还是"报价/浮动" | note 含"报价/浮动/地区"的不得渲染成"免费" | **失败 3 处**：Devin Teams/Enterprise、ChatGPT Go、Manus 个人档 |

## 三、沉淀成可重复执行的检查

单次手测不算完，三条检查应固化：

1. **`deploy/agent-health-check.sh`**：把 D06/D07 + I01/I02 + E02/E03 写成断言（约 16 条），并入 `run-all.sh` 部署后自动跑。
2. **`data-pipeline/scripts/check-agent-sources.py`**：把 S02 的 19 条 URL 可达性检查落成脚本，每周跑，失效链接自动告警。
3. **D07 的类型级防护**：`AgentProduct.bestModel` 改为引用 `UI_MODELS` 的 id 而非手写分数，让"分数写错"在编译期就不可能发生。
